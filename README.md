# Flappy Fly

An experiment toward training a controller based on the full retained MaleCNS
fly connectome to play a small Flappy Bird environment.

Current status: the deterministic game, pinned neural simulator, dataset
verification, and a bounded full-map benchmark are implemented. **No Flappy Bird
policy has been trained yet.** Benchmark frames are generated by a scripted
controller; its game score is never presented as the fly's performance.

The first cloud run measures whether full-network responses are fast enough to
support a useful training budget. It keeps the full retained graph, including
weak and self connections, using the upstream inclusion policy. This means all
neurons with assigned neuronal superclasses, excluding glia and unresolved
objects; it does not mean every object in the raw reconstruction.

## Run locally

Python 3.12+ and a C++17 compiler are required. The complete data preparation also
requires the pinned packages in `requirements.txt`.

```sh
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python scripts/prepare_data.py
python scripts/benchmark.py
```

The download is about 1.11 GB. Normalization and graph construction need
additional disk and RAM. Source files and prepared graph arrays are checked
against the pinned upstream SHA-256 manifests.

A separately labeled random-graph scale check needs only NumPy and a C++ compiler:

```sh
python scripts/benchmark.py --synthetic --output results/synthetic-scale.json
```

This synthetic check measures storage and exercises the integration path. Its
runtime is not a prediction of the real fly graph's runtime.

## GitHub Actions

The manual `Full fly map benchmark` workflow uses a standard Ubuntu runner and
has a 20-minute job limit. It saves small reports for three days, not the large
dataset. No personal access token is needed by the workflow.

Standard hosted runner compute is free for public repositories. Private
repositories use the account's included monthly allowance and can incur charges
when applicable limits are exceeded. Publication and the first dispatch are
separate steps; the workflow has no push, pull-request, or schedule trigger.

The reports contain node/edge counts, source hashes, peak process RAM, per-decision
runtime, and the projection of runtime for 10,000 decisions. That projection
excludes training overhead and long-term throttling.

## Next experiment

Use measured throughput to choose the neural time per game decision and a
checkpointed training budget. Train on one set of pipe-layout seeds and evaluate
on unseen seeds. Compare with frozen learning, shuffled connectivity, and simple
controllers. Record which parameters are trained; a trained output decoder is
not evidence that all biological connections learned the game.
